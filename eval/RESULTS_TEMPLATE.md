# PIXEL: Evaluation Results

> Template (protocol version 3). Every value below says **not run** until it is filled. Never write a number that was not measured. A metric the logs cannot support says **not measurable (gap: …)**.
>
> Two kinds of evidence are reported, and they are **never combined**:
> - **Part A — automated (mocked) tests.** A scripted model, a blank fake screen and mocked input. They show how the code reacts to given inputs, not how the agent behaves on a real desktop.
> - **Part B — real-desktop trials.** Only trials with a trial record (`eval/results/meta/`) count.
>
> Sources for Part B: automatic files `auto_trials.csv`, `auto_steps.csv`, `auto_calls.csv` (regenerated by `eval/summarize_runs.py`, never edited by hand), and the human sheets `trials.csv`, `steps.csv`, `sessions.csv`. Every Part B number says which source it comes from.

## B7. Limitations and interpretation

- n = 3 per cell: 3/3 ≈ 95 % CI [0.44, 1.00]; 0/3 ≈ [0.00, 0.56]. No significance tests between conditions. Pooled CIs treat different cells as one population and are descriptive only.
- One machine, one model version, three apps, specific dates. No generalisation beyond them.
- The visual verifier is the same model as the planner. Only the Notepad file tasks have a deterministic check.
- Part A results say nothing about grounding accuracy, verifier accuracy or real stop latency.
